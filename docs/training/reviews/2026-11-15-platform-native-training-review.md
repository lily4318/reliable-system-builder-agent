## 3. 三種工作方式與架構取捨

| 面向 | 教材團隊（摘要） | 既有研究網站開發 Agent（前次觀察） | Reliable System Builder Agent |
|---|---|---|---|
| 目標 | 業務團隊重用 | 特定網站交付及維護 | 通用工程任務及能力遷移 |
| 工作入口 | 角色與 SKILL | 專案 AGENTS、排程、正式來源 | START_HERE、AGENTS、catalog、role |
| 知識 | 品牌手冊、共用資料、案例 | 專案規格、進度、程式與測試 | 版本化工程技能、案例、決策，專案資料仍獨立 |
| 工作驗收 | 業務成果及覆盤 | 實際程式、CI、遠端、UI 與獨立啟用門檻 | 保留工程守門；已支援多種受控功能回歸 |
| 學習 | 案例與蒸餾 | 依實際缺陷改善專案 | 結構化回饋、詞彙檢索、候選知識、需審查與遷移證據 |

專案式 Agent 的真實工程工作可以作為概念上的學習來源，但搬移案例、共用能力、讀寫外部專案、修改排程均需另授權。不能把專案行政紀錄或敏感來源發布到公開 Agent repo。

三選項：A 本地 runner 為主要路徑，可控制模型與資源但多維護負擔，且不能代表其他模型；B 現有 AI 平台提供推理與工具，通用 repo 提供角色、技能、工作契約與知識，各專案保持獨立（TD-001 採用）；C 重新訓練 LLM 權重，非需求、不採用。日常工作不要求額外模型；本地推論或平台真的具有獨立子代理時才按授權與證據實際評測。單 Agent 角色切換、工作實際完成、獨立多 Agent、模型改善四者分開。
