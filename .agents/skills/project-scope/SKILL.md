# project-scope｜專案範圍與交付規劃
主責 project-manager；產物 delivery-scope。讀 AGENTS、角色、目標專案最新正式需求與授權。需求訪談先由 project-intake/requirements-spec 完成；scope 草案可在訪談中整理，但正式 handoff 需 current specification 及使用者確認，不將草案/前置產物當施工授權。

一頁交付約定：目的/受眾、MUST（含必要安全品質）、Should/Could/本期不做、最小可用成果、可操作驗收、階段及目標日期、工作包上限、成本上限、依賴/人工授權、停止點。估算列假設與不確定性；日期未定明標，不承諾背景執行。已有答案直接沿用，規模小不增多餘表單。技術方案由 Architect 評估、System Lead 拆包；PM 要求簡單足夠方案。需使用者決定之項目給可編輯選項及理由，不自行核准。
研究/實驗/教學須按需確認研究或學習目的、流程/隨機/參數/時序、資料欄位及匯出、可重現性、適用倫理/隱私與驗收；不必對純靜態教材設 DB 或登入。不把教學模擬當真人實驗或科學精度驗證。確認後保存至原規格/決策，私人工作台依原 handoff，REPO_NATIVE 用實際來源；不將私人資料寫公開 repo。重大修訂重新確認並依現有 revision/recovery 規則重驗。
