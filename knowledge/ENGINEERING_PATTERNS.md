# 共用工程知識（通用原則，不是正式專案規則）

## 預約及名額一致性
適用：多人可同時報名的服務。Architect 先定義狀態、唯一報名鍵、容量檢查與交易邊界；Developer 不採單純先讀剩餘名額再無鎖寫入。QA 以重複、額滿、同時提交及重試測試。依實際資料庫確認交易及唯一約束語法。未經實測不能宣稱已防競寫。

## 不明寫入復原
適用：具副作用 API 的逾時或部分寫入。先查實際遠端狀態及前後版本；不得盲重送。既有 src.recovery_reconciler、src.engineering_workflow 提供離線判定與回歸；外部操作另需授權。

## 需求修訂後的交接
先標記受影響的需求、架構、任務和測試，重新檢視必要依賴。src.team_workbench 只偵測已登錄產物版本相依，不取代工程語意查核。以實測及實際使用者回饋更新案例知識，失敗與限制一併保存。
