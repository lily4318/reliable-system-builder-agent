## 官方來源
- MDN [Performance.timeOrigin](https://developer.mozilla.org/en-US/docs/Web/API/Performance/timeOrigin) 各導航 context 的相對時間基準；同一 attempt 的 response/onset 才可在同一原點下相減，不以跨文件直減或 Date.now 補 RT。
- MDN [Using IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)、[IDBTransaction complete](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event)、[IDBTransaction durability](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/durability)：不要倚賴 unload 保存，交易 complete 而非單 request success 才表示提交；strict 是耐久性提示不是斷電保證。原生瀏覽器資料有生命週期與清除風險，不能當雲端收據。與原 GAS-DATA-003 同一原理：已提交而回應遺失須讀回，而不是盲重送；本機 SQLite 的交易隔離不能套給 Sheets batch。
- 方案 A 記憶體/離頁才存（不採）；B IndexedDB 原生 origin 儲存（本機環境阻擋，未驗）；C 真本機 Chromium about:blank DOM + Playwright host binding + SQLite 臨時檔（採用，可驗文件生命週期與真正後端交易，但非 HTTP/GAS/IndexedDB）。初次 https://trial.test/、loopback route 和純 file:// 三種導航皆被環境 ERR_BLOCKED_BY_ADMINISTRATOR；各9 setup errors，未跑到功能。停止該路徑，不改安全設定或試圖存取受限制資源。改為離線空白頁 set_content，只執行自寫 HTML/JS，reload 真文件後由 host 補入固定內容。沒有外部連線或真實網站。
