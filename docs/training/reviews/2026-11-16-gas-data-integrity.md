## 官方來源與取捨（查核日 2026-11-16）
- [LockService](https://developers.google.com/apps-script/reference/lock/lock-service)、[Lock](https://developers.google.com/apps-script/reference/lock/lock)：ScriptLock 同一 script、UserLock 每使用者、DocumentLock 在 Web App/standalone 無文件可能 null；取得 lock object 不代表取得鎖，tryLock false / waitLock throws，finally 釋放。SpreadsheetApp pending writes 在釋放前 flush；flush 不是原子交易、rollback、跨服務提交或 Advanced Sheets API 的必要 flush。鎖不保護其他 script/直接 API/人工修改；所有 writers 同一授權與寫入入口，包含 triggers/admin/import；鎖內重新讀 immutable logical id、容量、receipt，再計算；鎖外避免通知/長等待。
- [Sheets batchUpdate](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate)、[batch](https://developers.google.com/workspace/sheets/api/guides/batch)：單一 spreadsheetId 一次請求依序驗證/原子套用；不保證協作者不改結果。不可把多次 setValues、appendRow、flush、跨 workbook、Drive 檔案或 Gmail 發信當 ACID。批次 read/compute/write 不是可序列化隔離、Sheets 無通用 SQL unique/FK/CAS；鎖和 single writer 是設計前提，不是假稱 Google DB。一次 batch 同步寫名額/研究資料/持久 receipt/稽核/outbox，原始資料、版本、actor/project/study/operation/target/token/digest 固定；拒絕決策也需明確語意，replay 歷史 outcome 不是當前狀態。可信 server identity 授權每個操作（匿名需獨立核准的非特權流程及 server-issued correlation，token 不代替 auth），不使用客戶端 email 或部署者 fallback。
- [ValueInputOption](https://developers.google.com/workspace/sheets/api/reference/rest/v4/ValueInputOption)、[UpdateCellsRequest](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/request)：values API 用 RAW（不自動解析），spreadsheets.batchUpdate 用明確 userEnteredValue.stringValue/numberValue 等型別，而不是把 RAW 參數套錯 API；避免公式注入、id 前導零/日期等隱式轉換。UpdateCells 的 range 未完整覆蓋可能清除 masked 欄位，使用明確範圍與 field mask；保留未知欄與原始資料，不直接全表覆蓋。RAW 不是 CSV/Excel 再開啟的安全保證，另驗 export。lab 只測 JS 字串保持，非真 Sheet。
- [CacheService](https://developers.google.com/apps-script/reference/cache/cache-service)：cache 可提前消失，絕不用它當唯一 receipt/鎖/真資料/權限。PropertiesService 有大小/讀寫限制且非與 Sheets 共同交易；不可當可靠跨系統 commit ledger。
- [Sheets limits](https://developers.google.com/workspace/sheets/api/limits)（頁面 2026-09-03）：read/write 各 300/min/project、60/min/user/project；batch 算一次；180s request processing timeout；建議 payload <=2MB 非硬限制；429 bounded truncated exponential backoff+jitter。頁面 pricing 提及超額計費計畫 later 2026，須實際核最新帳戶/billing，不能保證超額免費，不啟用付費或自動升 quota。[Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas)：consumer/Workspace 一般 execution 6min，simultaneous 30/user、1000/script；trigger total runtime 90min/day vs 6h/day，Mail recipients 100/day vs 1500/day；每日限額依使用者首次請求後24h，會變動；相關服務另有限額。[Best practices](https://developers.google.com/apps-script/guides/support/best-practices)：批次讀寫、少 RPC、分段 checkpoint，勿按每筆 trial 每個 keypress 寫多次；依研究方法/資料耐久需求取捨，不能因 batch 效能而遺失未確認 trial；失敗分明確未送/確定拒絕/未知已送，已送逾時先對帳，不套盲重試。日配額耗盡停止/排隊/提示、節流重試受限，不在持鎖時 sleep；容量估算需原帳號全部流量、實際峰值、鎖等待、讀寫與 worker/備份開銷，配額不是吞吐保證。
- [MailApp](https://developers.google.com/apps-script/reference/mail/mail-app)：getRemainingDailyQuota 是當次執行的剩餘收件者人數，非預留，不等實際送達。研究報名與通知分開；同 workbook 原子 outbox，工作者另授權處理；失回應/已送未知保留 SENDING/UNKNOWN，不能因未標記 SENT 就自動重寄，需供應商可驗 idempotency 或安全人工對帳；不宣稱 MailApp exactly once。外部 PDF/Drive 同理、receipt 不代表外部完成。
- [Google Docs Editors Help 版本歷史](https://support.google.com/docs/answer/190843)：可從舊版本另存副本，直接 restore 可能影響既有格子編輯歷史。先停 writer/trigger 及任何在途 mutation、保存當前原件/ACL/稽核、記 checkpoint/revision/data dictionary/可信清單及 hash，複製到隔離 workbook restore，核資料+receipt+audit+outbox+pending、唯一 ID、數量與逐值、公式/raw 值/ACL/外部附件與程式版本相容。核備份後的新寫入並對帳，不把舊 backup 覆蓋現行或自動重發中斷通知。RPO/RTO、頻率、加密/權限/保存期限依研究者與倫理規格核定。版本歷史不是獨立備份或零遺失保證。

## 新垂直切片：unknown in-flight fence
比較 A user lock/cache receipt/逐步寫入（不採）；B script-wide lock + 同工作簿 batch + durable receipt + 在途 durable intent（受控模型採用）；C 高可靠 transactional backend（需真正約束、隔離、跨 writer 或高流量、極低 RPO/RTO 時提出，不能擅自遷移或使用付費）。B 不能推論 lock 自動釋放就不存在遠端在途請求。針對同一共享 invariant，在發送 batch 前先確認持久 intent 的確寫入；intent+business batch 本身為兩次操作，任何 intent 寫入/清除結果不明須停、查明，不把 absence of receipt 當未提交。batch 一次寫 row/capacity/receipt/audit/outbox + clear matching pending；不確定時所有受影響共享寫入 HOLD，唯讀對帳同 actor/token/payload。若確定原子批次拒絕且沒有在途寫入才清 intent；若 readback 證明已提交，驗完整 invariant 後續作；若一直無法確定則人工復原/另選具可證 fencing 的架構，不按 TTL 自動放行。這是保守失敗模型與風險假設，不聲稱 Google 文件保證逾時後會晚提交或提供 fencing/CAS；模型假設 intent 持久且已確認、單一 writer、遲到提交受控，不證 intent unknown、provider 無法讀取、崩潰前 intent 未 durable、分散多 writer、真正雲端可安全線性化。若不能可靠做到，停止或選真 DB，不以模型作生產程式。
