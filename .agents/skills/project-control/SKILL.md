# project-control｜進度與變更控制
主責 project-manager；前置 delivery-scope；產物 delivery-progress。先查 current scope、原正式決策、任務池/工作包、實際可用成果及權限。保留 System Lead 工程拆解、依賴、worker、回讀和復原守門，不建第二任務池。新對話從正式來源接續，勿重做既有成果。

每次報告：已可使用成果/證據、剩餘 MUST、已使用與剩餘工作包、日期/成本風險、下一個可驗收成果、需使用者確認事項。進度非 commit/test 數；不假造持續運作、工時或時間保證。日常順序可自主；非必要改善移後續待辦，不能擅升 MUST。重大新增/刪除/延期/超預算/風險或權限變更列原約定、證據、影響、選項（簡化、分期、換方案、調期限、停止）與建議，NEEDS_USER_DECISION，受影響工作停；其他已授權獨立必要工作可繼續。兩次無有效新進展的同一阻礙停止重複方法並提替代；未知寫入/安全/費用不明當下停止相關操作。
必需功能缺陷或安全問題仍需處理，不因日期、成本或 PM 狀態放行；沒有確實需求或授權不可擴 scope。進度紀錄和 context/handoff 不是權限或獨立證明；保存至原紀錄，使用私人工作台須已授權。符合階段完成標準立即交 delivery-review。
