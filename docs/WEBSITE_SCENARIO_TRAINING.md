# 六類新建網站需求情境｜公開合成評測與能力訓練（Draft PR #7）

本檔只適用 `lily4318/reliable-system-builder-agent` 自身的能力工作台。目標是練習**從 13 題訪談回答產生完整規格草稿、辨識應推導與不應推導的需求、逐項讓使用者選擇後修改再確認**，不是延續任何外部研究或正式網站工程。

## 需求案例（全部為合成資料）

| 案例 | 類型 | 主要考驗 |
|---|---|---|
| W101 | 合成研究活動資訊／報名 | 報名、時段、通知、資料同意、管理權限、現有 Repo；倫理核准不能推定 |
| W102 | 公開館舍靜態資訊 | **不需要**登入、報名、名額、通知、個資和整合時均不得誤增加功能 |
| W103 | 社區志工排班 | 報名／排班／權限需推導，但明示沒有通知或外部整合 |
| W104 | 少年運動課程 | 名額、簡訊、未成年資料與角色權限；不把敏感資料收件視為已授權 |
| W105 | 社區資源目錄／匿名回饋 | **不要報名但要匿名回饋**，需要分辨同一回答內的否定和肯定子句 |
| W106 | 企業內部知識平台 | 已答部分及未決的通知、資料、期程；不可擅自補值或核准 |

每例採用相同 13 題欄位；`evaluations/interaction/website-scenarios.json` 包含手動標註的 **expected**、**forbidden**（涵蓋現有六類推導）與 **expected_missing**，不宣稱獨立專家標註或封存盲測。

## 可直接重現

```bash
python -m src.website_scenario_eval validate
python -m src.website_scenario_eval packets --output output/website-scenario-tasks.json
python -m src.website_scenario_eval evaluate --output output/website-scenario-evaluation.json
python -m unittest discover -s tests -v
python -m src.quality_gate check
```

`packets` 只輸出各例的題目、13 題與使用者回答及工作指令，不包含任何預期推導標籤；適合未來由真正有權的 Agent runner 另行實作演練。`evaluate` 會**直接呼叫本 repo 的確定性 `build_spec`**，不是呼叫真正 LLM。若將來讀入外部 Agent 產物，必須和本地生成的結果分開存放，且對模型版本、執行記錄及人類審查另行採證。

## 規格完整性／推導／逐項確認量測

每個案例的以下七個檢查皆須通過：

1. **明示需求保留**：13 題均有來源欄，使用者回答保留；未答仍為「待確認」。
2. **完整規格草稿結構**：至少含功能與非功能規格、13 項需求來源追溯、架構設計待核草稿、執行與維運／測試待核計畫。**這只是結構完整性，不保證技術架構語意合理**。
3. **應有推導**：人工標註 expected 全部出現在候選建議。
4. **禁止誤推**：forbidden 必須全部不出現。特別檢查「不需要／不用／不收集／沒有」等否定及分句。
5. **未決欄位**：expected_missing 必須精確保持待確認，不得補成虛構答案。
6. **逐項可修改的確認**：每一推導都有「接受、修改、不採用」且可編輯；實際離線選擇→編輯→另行確認的 state machine 不會自動送出或核准。空的推導清單不要求無用的確認選項。
7. **無虛構授權**：規格、GitHub 寫入、部署、正式收件均不可由草稿或點選自動批准。

CI 品質閘要求至少六種不同情境、全部七項檢查通過，並斷言 `actual_LLM_execution_verified=false`、`model_skill_improvement_demonstrated=false`、`independent_blind_holdout=false`。測試還包含反例：把不要的通知加回去、刪除必需推導、拿掉架構欄、將送出設為自動、漏選項、假裝已部署或更動題庫標註，均需被拒絕。

## 已知限制與真正訓練的下一步

- 現有推導器是保守**關鍵詞加否定分句**規則，而非自然語意理解。可檢測明顯否定，但無法保證處理複雜跨句衝突、語意等價或使用者真正想要的最佳架構。任何推導仍由使用者核准。
- 題庫和標籤都公開、同一人建立，不是獨立 holdout；機械測試滿分只能證明已定義契約在合成案例上符合預期。
- 真實 Agent 成績需要**獲授權的模型 runner／真正執行記錄**，至少用未見題產生完整規格，再讓獨立人類盲態審查語意、推論品質與選項 UX。網站建置、正式資料或付費 API 均需另外的授權。
