# 使用者優先互動協定｜人工逐步教學、網站需求訪談、可編輯確認

適用本 Agent 在**被要求建置新網站**或**需使用者自行操作第三方帳號／設定**時。這是 Draft PR #7 的候選規則；並未合併 main、未啟用任何第三方服務。

## 規則 ①｜人工操作必須教到可以完成與查核

如需人類建立 GitHub 帳號、Repository、專案授權、網域設定、DNS、雲端帳號、CI Secret 或實際授權，先由 Agent 確認是否真有必要和權限；若 Agent 能安全合法操作，直接處理其有權操作的部分，**只把不可代行的部分交給人類**。不得僅說「請先完成 GitHub 設定」：

- **前提／目的**：為什麼需要、影響範圍、誰應具有管理權。
- **操作路徑與編號步驟**：提供平台、頁面、點選位置、欄位名稱及預期畫面；操作介面可能更新時以當次可見 UI 為準，遇差異不猜測。
- **完成確認**：每一步告訴使用者怎麼知道成功，最後只要求非敏感的完成證據（例如網址、狀態、錯誤碼、已遮蔽截圖）。
- **卡住的處理**：遇到找不到選項、權限不足、競寫或錯誤，說明停止的位置與接續方法；不要要求重做已完成步驟。
- **界線**：不要求使用者把密碼、OAuth、2FA 復原碼、Secret 值、API Key、私人的研究資料貼入聊天。不以使用者「可能完成」冒稱已驗證，不能以設定帳號自動取得寫入／部署授權。

現有 GitHub 操作手冊（真正需要時才提供相關版本）：

```bash
python -m src.human_walkthrough --task github_signup
python -m src.human_walkthrough --task github_repository
python -m src.human_walkthrough --task github_actions_secret
```

以上含每一步按哪裡和如何驗收；**這些是教學，不會透過程式建立帳號、Repo 或 Secret**。其他平台也需依同一契約提供專屬的逐步流程，沒有當前 UI 證據時明示可能差異並請用戶回報停住的畫面。

## 規則 ②｜一開始接新建網站，先訪談，不立刻寫程式

新建網站（不限研究招募網站）先問**13 題**，涵蓋：目的、使用者、核心流程、頁面素材、登入權限、表單資料、預約規則、通知、後台、隱私與核准、既有系統、外觀語言及無障礙、時程和驗收。**首次訪談總數控制在 10–15 題內**。如前文已清楚回答就先預填並請使用者核對，不要反覆提問；允許未決／不適用。若不必要，不要強迫使用者一次填超長表單，可分段或在一份可編輯草稿中收集。

```bash
python -m src.website_discovery questions
python -m src.website_discovery draft --answers /secure/website-answers.json \
  --output /secure/website-draft-spec.json
```

接受答案後，Agent 要自行思考：辨識流程關係、角色權限、表單／名額／通知／後台與品質需求等**可能遺漏功能**；但**每個推導都獨立標為「Agent 建議、待使用者確認」**，不得假定真實法規核准、網站已部署、使用者提供過不存在的細節，不能把研究網站的個資或流程照搬到新專案。

完成的規格草稿至少包含：目的與成功判準、目標族群、頁面與使用者流程、功能／非功能範圍、資料欄位及生命週期、角色權限、整合與基礎設施、例外／競寫／失敗、隱私法規與授權待核、正反測及驗收、MVP／後續版本、部署與維運、未決事項、**使用者明確需求與 Agent 推導需求的區分**。未決資訊用「待確認」，不亂補價格、期限或核准條件。明確展示規格讓使用者逐項**編輯、選擇與確認**，規格確認後才進入設計／候選開發；正式系統寫入、部署或收件仍要分開授權。

## 規則 ③｜可點選，點完可以修改，絕不選完即送

需使用者確認推導功能、架構方案、網站頁面、風險或下一步時：

1. 各待確認項目提供能直接點選的**選項**，必要時提供「其他／自訂」。
2. 使用者選擇時，**只預填編輯區**（textarea、可編輯草稿或等效的文字欄），明確顯示「尚未送出」。
3. 使用者可改選、編輯、移除、取消及預覽完整文字；選項不應鎖住草稿。
4. **只有**使用者在預覽後另外點「確認／送出」才傳送；若是敏感的外部寫入、實際部署、刪除或正式啟用，另外核對該動作的獨立授權，文字確認不等於已核准外部行動。
5. 若平台不支援真正可編輯的互動控制，提供每項可複製的完整文字與可編輯的自由文字欄或明示請直接修改文字後回覆；**不放會立即送出且沒有修改機會的選項按鈕**。
6. 不以使用者僅點選 radio／建議卡片作為核准、寄信、部署或不可逆操作的觸發。

可查看自含的唯讀示範 `examples/editable-decision-review.html`。Python 契約 `src.human_confirmation` 的 `select`、`edit`、`confirm` 故意**沒有傳送或核准外部動作的能力**，CI 測試選完、編輯、取消流程的拒絕條件。UI 示範僅在本地預覽，不連網。

### 可操作本機訪談介面
執行 python -m src.website_intake_ui，使用本機 Chrome 開啟顯示的 127.0.0.1 網址。可預填已有回答、逐項編輯及確認推導，完整預覽後明確確認才可匯出；修改回答會清除舊確認。詳細步驟與限制見 [13 題訪談介面](WEBSITE_INTAKE_UI.md)。此工具不使用 LLM 或外部服務。

### 六種公開合成建站需求的自動回歸
使用 `python -m src.website_scenario_eval evaluate --output output/website-scenario-evaluation.json` 進行六種不同網站的需求保留、應推導／不應推導、完整規格結構、個別編輯確認與無授權狀態驗證。否定句例如「不需要報名表單」不能被簡單關鍵字誤判；有「不需要報名，但需要匿名回饋」時需保留後一項需求。規格另生成 13 項需求來源追溯、架構與工作計畫待核草稿。案例屬人工撰寫且公開的**確定性邏輯回歸**；真正 LLM 的理解程度、適用介面與使用者體驗仍須獨立測試。詳見 `docs/WEBSITE_SCENARIO_TRAINING.md`。

## 與能力訓練及授權的關係

這三項是對話和工程需求品質規則，必須與 Agent 的既有能力基準、政策負測及正式發布守門一起驗證。合成單元測試 PASS 只表示本地契約有效；**尚未在真實 LLM、不同 UI 平台或真人網站專案完成使用者體驗測試**。下一輪可在獨立、取得允許的模型環境用陌生建站需求做真人評估，不得將這些文件誤稱已訓練底層模型權重。
