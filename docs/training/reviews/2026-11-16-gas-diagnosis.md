## 官方來源閱讀與因果模型（2026-11-16）
1. [部署與版本](https://developers.google.com/apps-script/concepts/deployments)、[Web App](https://developers.google.com/apps-script/guides/web)：HEAD 是目前儲存的檔案，/dev 為編輯者的測試入口；固定 version 不可變，deploymentId/URL 指向版本；更新原部署可改指新版本維持網址，新建部署則是另一資源。現有版本化部署所有權不隨專案轉移；擁有者帳號刪除、跨網域移轉或共用雲端硬碟移動可能致故障，實際新網域及 owner 先核；未授權不重部署。
2. [getContent](https://developers.google.com/apps-script/api/reference/rest/v1/projects/getContent)、[deployments.get](https://developers.google.com/apps-script/api/reference/rest/v1/projects.deployments/get)、[Deployment resource](https://developers.google.com/apps-script/api/reference/rest/v1/projects.deployments)：分別 GET HEAD、指定 versionNumber、指定 scriptId/deploymentId；核 deploymentConfig.scriptId/versionNumber、WEB_APP entryPoints.url 及 webApp.entryPointConfig.access/executeAs；分開記 origin Git SHA、已核轉換後完整檔案集合、HEAD、不可變 version、deployment pointer、實際 runtime marker/功能。版本號不等 Git SHA；不能只比 description、updateTime、檔案數或自報 marker。對 Git→GAS 名稱/型別/換行/manifest/建置轉換先定映射，核完整唯一 (name,type,source) 集合，不盲套檔案 SHA；未知生成物/漂移先停止。HEAD 可合法含未發布新工作，須先界定本次核對的是候選來源還是 active release，不因有差異就強制同步。
3. [updateContent](https://developers.google.com/apps-script/api/reference/rest/v1/projects/updateContent)：PUT 是 HEAD 全量替換，原檔案先清除，必須包含完整檔案與 appsscript JSON manifest，不能當單檔 patch。事前獨立授權、備份、source/target pin、單 writer/人工競寫風險控制、完整 readback；失回應或部分狀態先唯讀對帳，勿直重送；HEAD 更新不等運行版切換，建立 version、更新既有 deployment 都分別核對。未證 provider CAS 或跨系統交易；rollback 需舊 version 及現有資料 schema/副作用/寫入相容，不是自動回退。
4. [access/executeAs](https://developers.google.com/apps-script/manifest/web-app-api-executable)、[Session](https://developers.google.com/apps-script/reference/base/session?hl=zh-tw)、[授權](https://developers.google.com/apps-script/guides/services/authorization)：access 與執行身分分離；MYSELF / DOMAIN / ANYONE / ANYONE_ANONYMOUS。USER_DEPLOYING 以部署者授權執行，訪客 email 可能空白；USER_ACCESSING 由訪客身分執行，可能只授部分 OAuth scopes（檢查 ScriptApp.getAuthorizationInfo 及所需 scope）。有效執行者並非可信訪客身分；不得用 getEffectiveUser() 或客戶端 email/role 補空白。需識別的操作 fail closed；明確核准匿名公開的非特權入口可不識別但不得讀取管理/敏感資料。伺服端每個可呼叫 RPC/route 獨立授權，避免用部署者權限代理任意 Sheets/Drive 資源；不傳 OAuth token 到 client。Workspace 政策、OAuth app audience/test user、scope、backend ACL 分開。
5. [multi-login](https://developers.google.com/apps-script/guides/support/troubleshooting)、[Chrome Cookie](https://support.google.com/chrome/answer/95647?hl=zh-Hant)：保留原 GAS-ACCESS-SESSION-001，先對準同 URL/版本/預期角色、同一訪客帳號比較一般與乾淨工作階段；不同帳號或第三方 Cookie 差異可能是混淆，不直接診斷 Cookie 根因；無痕非万能，必要時隔離 profile；經知情同意才清相關 site data，告知登出/本機資料風險。不要求廣泛關閉安全。
6. [HTML Service RPC](https://developers.google.com/apps-script/guides/html/communication)、[Logging](https://developers.google.com/apps-script/guides/logging)：google.script.run 非同步、呼叫可能亂序；must success/failure handler、合理 pending/error UI，傳可支援原始值與 JSON-like 資料（Date、循環結構等不可直接傳），序列化及版本契約；每一公開函式鑑權，隱藏 UI 或 private helper 不代替授權。先看 DevTools Console/Network（不收原始 cookie/token/HAR），再 Apps Script 左側 Executions 的 Failed/Timed out、授權可用時 Cloud Logging；時間/非敏感 request id、函式/版本/角色對應，避免記 email、受試者資料、表單值。暫時 user key 僅診斷關聯、會變動，非登入身份或角色授權。RPC failure/timeout 可能已提交，不能等同未寫，依原收據/對帳規則。

## 取捨、操作與 QA 交接
方案 A 單看頁面是否開啟、Cookie 或 build marker 即下結論（不採用）；B 分層核目標、版本、work session、access/executeAs、RPC/資源與預期正反例（採用）；實際登入及部署驗收需要另行授權和工具，不能以合成診斷取代。優先順序：未知目標/錯 URL 或未知 mutation 先只讀停相關寫入；越權或不應存在的公開存取即安全 HOLD；再核 policy/版本；在可比較同身分 clean profile 試驗 session；仍失敗查角色/Workspace/OAuth；頁面已開但功能失敗查 RPC console、server Executions/資源；實際發布前測不同預期角色及匿名（僅核准時）、無權限管理負測、真版本與資料功能。表格保存各步 PASS/FAIL/NOT_TESTED、實際工具/環境、source SHA、version、非敏感證據與下一步。若 context 不可比較，只能列疑因不確證。介面按現有授權唯讀 Deploy > Manage deployments，選原部署讀 ID/版本/URL/設定；Project Settings 讀 Script ID；Executions 篩選；允許 API 才讀 metadata/content。如需變更或修改診斷標記，另明示授權；本輪一律不執行。不能把 OBSERVATIONS_CONSISTENT 當部署許可、真 UAT、所有角色或資料安全通過。
