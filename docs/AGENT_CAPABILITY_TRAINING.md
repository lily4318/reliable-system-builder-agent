## 已確認的能力目標

1. 深入 C#、MVC、SQL 原教材，寫得出正常、邊界和失敗處理。
2. 在陌生需求及中途改版時，說明請求、業務規則與資料的責任分界，能維護跨層設計。
3. 依需求交付可操作的完整網站或服務，驗前後台、資料與必要整合。網站、預約及 LINE／GAS／Sheets 各按任務取用。
4. 團隊自主完成可行工作。只有需決策或本人操作時才逐步引導使用者。
5. 新對話能依同一份進度接手。實質失誤轉為可重做的案例，再觀察下個任務有沒有改善。

工程專業持續居優先。期限、人力、可投入時間與實證能力依案評估。兩小時是過往使用經驗的參照。研究、實驗或教學個案的資料與需求保存在各案授權位置。

## 訓練方法

1. **先查全圖，再排本輪。** 對照十個位置、各職責和已驗能力，標出可沿用、需串接、待補建的部分。依目標、依賴與可取得材料選一個有價值的工作包。
2. **先定可交付的結果。** 重用已知需求。PM 與主責只補問會改變範圍的限制，按期限、可投入的人力／工時及同類作品或測試評估可行性。能力證據不足時列出一個最小試作，說明首版、可延後項及驗收。
3. **按職責學與做。** 讀完整來源，解釋因果，分析條件與反例，蒸餾出可用原理，整合進既有技能，自行實作並跑正反測及修復，最後換陌生任務交給下一角色驗收。逐單元依可重現證據判定 L0–L6。教材與真任務可並進。[穩定訓練準則](training/CORE_TRAINING_PRINCIPLES.md)
4. **交實物並覆盤。** 記錄實作、驗收方式、版本、結果、未驗與適用限制。改變長期做法時更新技能或工作手冊，單案例外存原案。下一輪讀回並觀察是否真的採用。

## 需求變更與接續

開工先讀本檔的「目前工作」，再讀適用的決策、任務書、技能與原案規格。在訓練候選分支內，分支連結始終指向最新版，指定提交只用於重播當時的證據。

使用者確認需求更新時，當輪替換本檔的有效文字，更新受影響的任務書、排程、角色或技能指引及驗收。原先完成的成果若不符新條件，標明待重驗。從現行入口與範本刪除過期條文及排程，將替換理由留在[決策紀錄](training/DECISION_LOG.md)。討論稿獨立標示。私人原話留在授權位置，公開檔僅保留通用方法及匿名證據。

收工回寫目前工作、已驗與未驗的界線、下一個可驗成果及負責人。驗接續時，請未讀前文的角色只從訓練入口接案，核對其需求版本、產物、證據及下一步。中途調整一項條件後，用相同方式再驗。

先前逐輪成果、原始記錄及當時的工程證據可依[整理前的完整快照](https://github.com/lily4318/reliable-system-builder-agent/blob/9f6e7049564c5a3aaba3d7040e018ad66adff56d/docs/AGENT_CAPABILITY_TRAINING.md)、[歷次覆盤](training/reviews/)與[工程經驗索引](../knowledge/ENGINEERING_PATTERNS.md)追溯。
